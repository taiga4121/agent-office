# E2E手動確認: feature/claude-chat-sessions

対象PR/変更概要: チャットにセッション管理(履歴一覧・新規セッション作成)を導入し、「新規セッション」を押しても切り替わらないバグを修正。あわせてClaude Code CLIと接続するローカルバックエンド(server.js)、実行前の許可ダイアログ、チャット履歴のlocalStorage永続化を追加。
確認環境: 実機（このリポジトリはWebアプリのためExpo Goは対象外。`npm run dev`でローカルサーバー起動、ブラウザで確認）。バックエンド起動手順・Claude CLIの準備は`/run-on-device`を参照。

## シナリオ1: 新規セッションボタンでチャットが切り替わる（今回の主要バグ修正）

前提: `npm run dev`でapp.js配信サーバーとserver.js(port 3001)が起動している。いずれかのプロジェクトの部屋を開き、チャットパネルが表示されている。

- [ ] 手順1: 既存セッションでメッセージを1件送信し、応答が表示されるまで待つ
- [ ] 手順2: 「+ 新規セッション」ボタンをクリックする
- [ ] 手順3: チャット本文エリアが空（「履歴なし」表示）に切り替わることを確認する
- [ ] 手順4: 新規セッションで別のメッセージを送信し、応答が表示されることを確認する
- [ ] 手順5: 「履歴」ボタンを押し、ドロップダウンに「現在の会話」と元のセッション（「会話 XX」）の両方が表示されることを確認する
- [ ] 手順6: 元のセッション（「会話 XX」）をクリックして選択する
- [ ] 期待結果: 手順1で送信したメッセージと応答のみが表示され、新規セッションで送ったメッセージは表示されない（セッションが正しく分離されている）
- [ ] 手順7: 再度「+ 新規セッション」をクリックし、新規セッション側に戻す
- [ ] 期待結果: 新規セッション側のメッセージのみが表示され、画面が固まらずチャット入力欄がすぐ操作可能になる

## シナリオ2: セッション履歴ドロップダウンの表示と切り替えのUI挙動

- [ ] 期待結果: クリック後ドロップダウンが自動的に閉じ、選択したセッションのメッセージ一覧に切り替わる
- [ ] 手順3: 再度「履歴」ボタンをクリックしてドロップダウンを開閉できることを確認する（開→閉→開の往復操作）

## シナリオ3: セッション/チャット履歴のリロード後の永続化

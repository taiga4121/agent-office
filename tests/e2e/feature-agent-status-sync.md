# E2E手動確認: feature/agent-status-sync

対象PR/変更概要: タスク送信後に固定4.2秒でidleへ戻していた強制autoReset処理を削除し、実際のClaude CLI処理完了/エラーを起点にステータス更新するよう修正。あわせてserver.jsでprojectIdごとの作業ディレクトリ切り替えと、stream-json出力からのサブエージェント(Task/Agentツール)起動・終了検知をSSE配信するようにし、app.js側でサブエージェントカードのWORKING/IDLE表示に反映する。

確認環境: ブラウザ(Vite dev server, `npm run dev`)+ ローカルNodeサーバー(`server.js`, port 3001)。起動手順は`/run-on-device`を参照。

## シナリオ1: メインエージェントのWORKING表示が処理完了まで維持される（正常系）

前提:
- agent-officeプロジェクトのチャット画面を開いている
- Claude CLIが実際に応答を返せる状態（`CLAUDE_COMMAND`等の環境設定込み）

- [ ] 手順1: agent-officeプロジェクトのチャット欄に、数十秒以上かかると見込まれる指示（例: 「READMEの内容を要約して」程度の軽いものではなく、複数ファイルを読ませるような重めの指示）を入力し送信する
- [ ] 手順2: 確認ダイアログ（実行許可パネル）が出たら承認する
- [ ] 手順3: 送信直後、agent-officeのMain Agentカードが即座にWORKING表示（💻アイコン、"Working"ラベル）になることを確認する
- [ ] 手順4: 送信から4.2秒経過した時点で画面を確認し、Claude CLIの処理がまだ終わっていなければMain AgentカードがWORKING表示のまま維持されている（誤ってIdleに戻っていない）ことを確認する
- [ ] 手順5: Claude CLIの処理が完了しチャットに応答が表示されるタイミングと同時に、Main AgentカードがIDLE表示（🧑‍💼アイコン、"Idle"ラベル、Activityが"Claude Code responded"）に切り替わることを確認する
- [ ] 手順6: 送信ボタンが「考え中」で無効化されていた状態が、応答受信と同時に「送信」に戻り再度押せることを確認する
- [ ] 期待結果: WORKING表示は実際のClaude CLI処理時間に追従し、4.2秒などの固定時間では変化しない。処理完了と同時にIdleへ戻る。

## シナリオ7: ページリロード後の状態確認（永続化観点）

前提:
- タスク実行中（Main AgentがWORKING表示、またはサブエージェントがWORKING表示）の状態を作る

- [ ] 手順1: いずれかのプロジェクトでタスクを送信し、Main AgentがWORKING表示になっている最中にブラウザをリロードする
- [ ] 手順2: リロード後、Main Agentのステータス表示が`public/projects.json`の初期値（Idle）に戻っていること（WORKING状態は永続化されておらず、リロードで見た目上リセットされる）ことを確認する
- [ ] 手順3: バックグラウンドのClaude CLIプロセス自体はリロードと無関係に動き続け、完了時にSSE/レスポンスがUIに反映されようとするが、リロード直後は新しいページ側では紐づくPromiseが存在しないため、その完了通知はチャット欄には反映されない可能性がある点を確認する（サブエージェントのSSEイベントのみ新しいページでも受信され、該当カードがWORKING→IDLEに変化することを確認する）

- [ ] 期待結果: エージェントの稼働状態(working/idle/error)はリロードで初期化されるが、チャット履歴は保持される。SSEは再接続され、進行中のサブエージェントイベントは新しいページでも引き続き受信できる。
